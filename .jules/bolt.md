## 2024-05-18 - Avoid executemany limitations for async database optimization

**Learning:** When trying to optimize batch query execution (like N+1 queries) in custom query layers that wrap ORMs/Drivers (like in `database_optimizer.py`), replacing a sequential loop with `connection.executemany` directly can be dangerous and complex. It strips away standard return types (row counts, last inserted IDs, fetched rows), skips centralized telemetry and cache logic built into the unified `execute_query` methods, and only works for homogenous DML queries anyway.
**Action:** For general-purpose batch endpoints in Python backend apps, prefer utilizing `asyncio.gather` on individual wrapped queries to achieve concurrency rather than forcibly subgrouping queries for `executemany` calls, unless the function is explicitly and strictly designated for bulk raw DML execution. This achieves significant performance improvements (e.g. 42ms -> 4.9ms for 100 queries) while maintaining safety, telemetry, and predictable return values.
